# 全員死亡後本機復活：實作與限制

目標條件：KK 對局已進圖、不修改或辨識特定地圖、只要求本機有效。

## 已確認的引擎入口

工作區 `WarcraftⅢ-11hf/Game.dll` 的 JASS Native 註冊表包含：

| Native | 簽名 | 本版 RVA |
| --- | --- | --- |
| `ReviveHero` | `(Hunit;RRB)B` | `0x1F3300` |
| `ReviveHeroLoc` | `(Hunit;Hlocation;B)B` | `0x1F3380` |
| `GetUnitX` | `(Hunit;)R` | `0x1E66B0` |
| `GetUnitY` | `(Hunit;)R` | `0x1E66F0` |
| `GetWidgetLife` | `(Hwidget;)R` | `0x1E6730` |
| `EndGame` | `(B)V` | `0x1E0100` |

這些 RVA 只適用於本工作區已核對 PE 指紋的 1.27 `Game.dll`。`ReviveHero` 的實參需採 JASS wrapper 的 x86 ABI；`real` 應傳浮點值指標，不能把 C++ `float` 直接當值傳入。`EndGame` 是一個可觀察的引擎入口，但不能假設所有地圖的失敗流程都會呼叫它。

## 通用本機功能能做到的事

已加入以下指令，可從 CLI 或 GUI 指令框使用：

| 指令 | 行為 |
| --- | --- |
| `!revive` | 掃描本機玩家地圖內的英雄，立即嘗試復活已死亡者一次。 |
| `!autorevive` | 掃描並記錄本機英雄，之後約每 50 毫秒檢查死亡狀態並嘗試復活。 |
| `!autorevive stop` | 關閉監看並清除記錄。 |

建議在英雄仍存活時啟用 `!autorevive`。DLL 記錄英雄 handle、單位種類、擁有者及最後座標；每次檢查會核對同一 handle 是否仍代表該英雄。復活只嘗試一次，直到英雄再次恢復生命值；結果記錄 `ReviveHero` 回傳值及復活後生命值。英雄消失、玩家或 Game.dll 變更、遊戲視窗關閉時停止監看。啟用前核對 Game.dll PE 指紋與各 Native 入口位元組。`!compat` 顯示 `ReviveHero` 入口與監看狀態。

它**無法保證**「全員死亡後地圖繼續」：地圖可能在最後一名英雄死亡的同一事件中執行失敗觸發器、刪除英雄、停用復活計時器、設定自訂全局旗標，或直接結束遊戲。定時檢查通常來不及阻止同一事件中的失敗判定；即使本機 `ReviveHero` 成功，也不會自動重置地圖自訂狀態。`EndGame` 亦不是所有失敗路徑的通用開關。

## 結論與驗證順序

不綁定地圖時，這是**本機盡力復活**，不是對所有地圖都有效的「全死仍按原流程復活」。編譯與 mock 回歸測試可以驗證指令路徑和本機狀態機；仍需在可重開的遊戲測試局驗證實際 ABI、死亡後 handle 是否仍存在、生命值及失敗畫面，再測 KK 對局是否斷線或狀態分歧。若需要保證某張地圖的原有復活流程在全員死亡後仍執行，必須找出該地圖的失敗條件或復活觸發器；不能只靠通用 Native 呼叫保證。
